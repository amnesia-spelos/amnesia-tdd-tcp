# Avatar mesh and animation assets to ship

Source snapshot for the engine-loader findings: commit `ecb10df`. Paths and line numbers below are relative to the repository root. This note addresses the asset format choice for the Avatar model. Since #42, the Avatar loader also reads the `.ent` animation entries. The Grasp articulation spec (#47) uses source assets and ModelView during authoring; the binary-only runtime set below is a packaging recommendation to validate separately, not a prerequisite for #47.

## Recommendation

Ship the `.ent`, a **`.msh` mesh, and separate `.anm` clips**, with the `.ent`/Avatar asset references changed to those exact binary filenames. Also ship the materials and textures referenced by the mesh. Keep `.dae` and `.dae_anim` as editable/build inputs outside the runtime distribution. The engine registers `.msh` and `.anm` as directly loadable formats, and the binary mesh records material names, its skeleton, and any embedded animations; standalone `.anm` records animation tracks, not another copy of the mesh geometry ([`LowLevelResourcesSDL.cpp:76-84`](../../src/HPL2/core/sources/impl/LowLevelResourcesSDL.cpp#L76-L84), [`MeshLoaderMSH.cpp:87-129`](../../src/HPL2/core/sources/impl/MeshLoaderMSH.cpp#L87-L129), [`MeshLoaderMSH.cpp:173-195`](../../src/HPL2/core/sources/impl/MeshLoaderMSH.cpp#L173-L195), [`MeshLoaderMSH.cpp:314-328`](../../src/HPL2/core/sources/impl/MeshLoaderMSH.cpp#L314-L328), [`MeshLoaderMSH.cpp:472-479`](../../src/HPL2/core/sources/impl/MeshLoaderMSH.cpp#L472-L479), [`MeshLoaderMSH.cpp:533-546`](../../src/HPL2/core/sources/impl/MeshLoaderMSH.cpp#L533-L546), [`MeshLoaderMSH.cpp:564-650`](../../src/HPL2/core/sources/impl/MeshLoaderMSH.cpp#L564-L650)).

This is a runtime recommendation, conditional on generating binaries with the **same engine format version** used by the game and checking the referenced materials/textures. The binary loader rejects a version mismatch ([`MeshLoaderMSH.cpp:100-116`](../../src/HPL2/core/sources/impl/MeshLoaderMSH.cpp#L100-L116), [`MeshLoaderMSH.cpp:493-525`](../../src/HPL2/core/sources/impl/MeshLoaderMSH.cpp#L493-L525)).

## Why filename references matter

`CreateMesh` and `CreateAnimation` first resolve the requested filename through `FileSearcher`, then dispatch to a loader. The contemplated `.dae` → `.msh` fallback in `MeshManager` is commented out. Thus a reference to `avatar.dae` with only `avatar.msh` present is not a supported runtime lookup; likewise `walk.dae_anim` with only `walk.anm` present. Use explicit `.msh` and `.anm` references if shipping binaries alone ([`MeshManager.cpp:70-128`](../../src/HPL2/core/sources/resources/MeshManager.cpp#L70-L128), [`AnimationManager.cpp:62-110`](../../src/HPL2/core/sources/resources/AnimationManager.cpp#L62-L110), [`ResourceManager.cpp:191-193`](../../src/HPL2/core/sources/resources/ResourceManager.cpp#L191-L193)). The `.ent` loader passes its `Animations` entry's `File` attribute to `CreateAnimation` after resolving a bare filename relative to the `.ent`; it does not rewrite extensions ([`EntityLoader_Object.cpp:435-455`](../../src/HPL2/core/sources/resources/EntityLoader_Object.cpp#L435-L455)).

Collada loading *does* check for same-stem `.msh`/`.anm` caches and can use them if newer than source, forced, or the source is absent. That check runs only **after** the resource manager has found the requested source path. Thus shipping `.dae` + `.msh` but no `.dae_anim` + `.anm` can work only if the animation references are explicitly changed to `.anm`; the pair is otherwise an unnecessary duplicate for a binary-only release ([`MeshLoaderCollada.cpp:179-200`](../../src/HPL2/core/sources/impl/MeshLoaderCollada.cpp#L179-L200), [`MeshLoaderCollada.cpp:805-825`](../../src/HPL2/core/sources/impl/MeshLoaderCollada.cpp#L805-L825), [`MeshManager.cpp:70-128`](../../src/HPL2/core/sources/resources/MeshManager.cpp#L70-L128), [`AnimationManager.cpp:62-110`](../../src/HPL2/core/sources/resources/AnimationManager.cpp#L62-L110)). The game's `ForceCacheLoadingAndSkipSaving` setting defaults to true in `LuxConfigHandler`, so a `.dae` reference with both files present favors cache loading, but this does not remove the initial source-path lookup requirement ([`LuxConfigHandler.cpp:73`](../../src/amnesia/src/game/LuxConfigHandler.cpp#L73), [`LuxBase.cpp:1262`](../../src/amnesia/src/game/LuxBase.cpp#L1262), [`MeshLoaderCollada.cpp:185-200`](../../src/HPL2/core/sources/impl/MeshLoaderCollada.cpp#L185-L200)).

## Comparison

| Runtime set | Result |
| --- | --- |
| `.dae` + `.dae_anim` | Loads through Collada and writes `.msh`/`.anm` caches unless forced cache mode blocks cache saving. Requires parsing source when no usable cache exists ([`MeshLoaderCollada.cpp:179-200`](../../src/HPL2/core/sources/impl/MeshLoaderCollada.cpp#L179-L200), [`MeshLoaderCollada.cpp:755-761`](../../src/HPL2/core/sources/impl/MeshLoaderCollada.cpp#L755-L761), [`MeshLoaderCollada.cpp:805-825`](../../src/HPL2/core/sources/impl/MeshLoaderCollada.cpp#L805-L825), [`MeshLoaderCollada.cpp:975-984`](../../src/HPL2/core/sources/impl/MeshLoaderCollada.cpp#L975-L984)). |
| `.dae` + `.msh`, `.anm` only for clips | Valid if animation references say `.anm`. Mesh references can remain `.dae`, but the `.dae` must still be discoverable; this ships duplicate mesh representations ([`MeshManager.cpp:70-128`](../../src/HPL2/core/sources/resources/MeshManager.cpp#L70-L128), [`EntityLoader_Object.cpp:435-455`](../../src/HPL2/core/sources/resources/EntityLoader_Object.cpp#L435-L455)). |
| `.msh` + `.anm` only | Preferred runtime set when all references use binary extensions. Direct loader support avoids source lookup and duplicate source files ([`LowLevelResourcesSDL.cpp:76-84`](../../src/HPL2/core/sources/impl/LowLevelResourcesSDL.cpp#L76-L84), [`MeshLoaderMSH.cpp:62-63`](../../src/HPL2/core/sources/impl/MeshLoaderMSH.cpp#L62-L63), [`MeshLoaderHandler.cpp:57-90`](../../src/HPL2/core/sources/resources/MeshLoaderHandler.cpp#L57-L90)). |

ModelView can open `.dae`, `.dae_anim`, and `.msh`, and its animation picker accepts `.dae_anim`; the actual binary cache creation occurs in the Collada loader on load, when cache saving is enabled. The executable alone is therefore not a special export dependency; the engine's matching loader version and generated files are what matter ([`ModelView.cpp:874`](../../src/HPL2/tools/modelview/ModelView.cpp#L874), [`ModelView.cpp:1916-1938`](../../src/HPL2/tools/modelview/ModelView.cpp#L1916-L1938), [`MeshLoaderCollada.cpp:755-761`](../../src/HPL2/core/sources/impl/MeshLoaderCollada.cpp#L755-L761), [`MeshLoaderCollada.cpp:975-984`](../../src/HPL2/core/sources/impl/MeshLoaderCollada.cpp#L975-L984)).
